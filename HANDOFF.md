## 1. Что вам передают

Работающую агентскую орг-структуру группы продуктов ОКОЁМ: три product-owner агента с единым CPO, борд из девяти C-ролей, два расписания, полный свод правил и первый прогон, который уже нашёл три вещи, требующие действий.

Компания: ОКОЁМ — рабочая среда для помогающих специалистов (психологи, коучи, профориентаторы), РФ. Учредитель — один человек, Илья. Все остальные роли исполняют агенты. Продукты:

| Продукт | Что это | Репозиторий |
|---|---|---|
| **ПРАКТИКА** | рабочая среда специалиста: запись, календарь, карточки клиентов | `compas-psy/cmpas.ru` |
| **ЗАПИСКИ** | заметки о сессиях, самый чувствительный продукт | `compas-psy/zapiski` |
| **МОМЕНТЫ** | медитации и практики, standalone для конечного человека | `compas-psy/compas-voice` |
| — | операции: борд, бэклог, деки, инструменты | `compas-psy/compas-ops` |

## 2. Первое, что нужно понять про среду

Система была собрана в облачной песочнице Cowork, у которой **нет выхода в интернет** — открыты только реестры пакетов и GitHub. Отсюда два следствия, определившие всю архитектуру:

1. Telegram оттуда недостижим. Поэтому доставка построена через GitHub Actions: агент кладёт файл в `outbox/`, воркфлоу отправляет его в Telegram с раннера, у которого интернет открыт. **У вас Telegram доступен напрямую — можете отправлять сами, но воркфлоу оставьте: им пользуются ночные запуски по расписанию, которые идут в той же песочнице.**
2. Память системы жила в документах проекта КОМПАС на claude.ai, потому что проект доступен любой сессии всегда. **Вам проект недоступен.** Поэтому всё содержимое проекта скопировано в этот репозиторий — `charter/`, `state/`, `log/`. Дальше правило меняется: **первичное хранилище — репозиторий**, а проект остаётся зеркалом для облачных сессий. Синхронизацию надо будет наладить, см. §7.

## 4. Как это работает

**Ночной цикл, ежедневно 05:00 МСК.** Три PO параллельно читают данные, сигналы, бэклог и свой репозиторий, каждый даёт бриф по шаблону `04_TEMPLATES §1`. CPO делает merge: снимает дубли, разрешает конфликты за инженерный ресурс, проверяет связность между продуктами, обрезает по ёмкости от CTO, собирает план дня. Обновляются бэклог, очередь задач учредителю и журнал. Сводка уходит учредителю.

**Борд C-1, понедельник и четверг 10:00 МСК.** Девять ролей: CEO, COO, CPO, CMO, CTO, CFO, Senior Legal, главный бухгалтер, InfoSec. Повестка жёсткая: контроль исполнения прошлых решений, три числа (деньги, продукт, доверие), круг ролей по одному риску и одному запросу, портфельный приоритет на 3–4 дня, срочные вмешательства в бэклог, спорные вопросы. Выход: дек 5–9 слайдов, журнал решений, обновлённый бэклог, очередь задач учредителю.

**Граница человека и агента — устав §6, соблюдать строго.** Агенты не тратят деньги, не заключают договоров, не публикуют ничего от лица бренда, не пишут реальным людям, не выкатывают в прод, не меняют цены и оферту, не касаются персональных данных пользователей и содержания клиентских заметок. Всё это оформляется задачей учредителю по формату `04_TEMPLATES §4`: что сделать одним глаголом, почему не агент, что заблокировано, сколько минут, готовая рекомендация.

**Правило честности данных.** Нет свежих выгрузок — агент пишет «данных нет» и предлагает недостающую инструментовку. Выдуманная цифра в ночном брифе — худшее, что может произойти, потому что через два дня на ней построят решение.

**Общее для всех трёх продуктов.** Разметки событий нет нигде. Ни один из 39 порогов алертов не проверяем. Спецификации событий для ПРАКТИКИ и МОМЕНТОВ уже написаны PO и лежат в журнале ночного цикла, их можно брать в работу как есть.

## 6. Что заблокировано и чем вы это разблокируете

Всё это упиралось в среду Cowork. У вас этих ограничений нет — закройте по порядку.

1. **Права на запись в `compas-ops`.** Из песочницы прокси отказывал. Вы просто коммитите.
2. **Чтение `cmpas.ru` и `compas-voice`.** Из песочницы недоступны, поэтому два PO из трёх работали вслепую. Первое, что стоит сделать, — прогнать по ним тот же разбор, что PO-ЗАПИСКИ сделал по своему репозиторию: состояние разработки, расхождение кода с документами, гигиена секретов, публичность.
3. **Telegram.** Положите `TG_BOT_TOKEN` и `TG_CHAT_ID` в Settings → Secrets and variables → Actions. Токен, который был прислан в переписку, отзовите через `@BotFather` → `/revoke` и выпустите новый. Проверка: вкладка Actions → «Доставка в Telegram» → Run workflow.
4. **Данные.** Ни одного подключённого источника аналитики. Первая волна по `charter/03_SOURCES.md §5`: биллинг, Яндекс.Метрика, AppMetrica. Биллинг первым — деньги единственная метрика, не требующая инструментовки в коде.

Открытые задачи учредителю на момент передачи — пять, полные формулировки в `state/11_HUMAN_QUEUE.md`: решение о публичности `zapiski`, утверждение формулировки вместо невыполняемого обещания, токен бота, подключение репозиториев, первый срез данных.

## 7. Расписания

Два запуска живут в облаке Cowork и продолжат идти оттуда: ночной цикл ежедневно в 02:00 UTC (05:00 МСК) и борд по понедельникам и четвергам в 07:00 UTC (10:00 МСК). Каждый запуск — новая чистая сессия, поэтому промпт самодостаточен: он велит агенту прочитать документы, отработать протокол и записать результат.

**Развилка, которую надо решить сразу.** Облачные запуски читают документы из проекта КОМПАС, а вы работаете с репозиторием. Два хранилища разъедутся за неделю. Варианты:

- **Оставить облачные запуски и синхронизировать.** После каждой своей правки в `charter/` и `state/` обновлять соответствующий документ проекта. Надёжно, но требует дисциплины или отдельного шага в CI.
- **Перенести ритм к себе.** Отключить оба расписания в Cowork и запускать ночной цикл и борд из Claude Code по cron или через GitHub Actions с вызовом Claude Code. Тогда репозиторий — единственная память, и расхождению неоткуда взяться. Это чище, и я бы рекомендовал именно это, как только у вас всё заработает.

Полные тексты обоих промптов — в `charter/06_DELIVERY.md` и в описании расписаний; они переносятся в ваш раннер без изменений, кроме шага доставки: у вас Telegram доступен напрямую, скрипт `tools/tg_send.py` работает как есть, ему нужны только переменные окружения `TG_BOT_TOKEN` и `TG_CHAT_ID`.

## 8. Инструменты

`tools/tg_send.py` — отправка в Telegram, только стандартная библиотека, без зависимостей. Подкоманды `text`, `file`, `photo`; нарезка длинных сообщений по границам строк; экранирование HTML; ретраи с backoff, честная обработка `retry_after` на 429; мгновенный отказ без повторов на 400/401/403; `--dry-run`.

`tools/make_deck.py` — генератор дека борда. Вход — markdown-подобный файл: слайды разделяются `---`, поддерживаются заголовки, буллеты, таблицы, блоки `@metric`, `@status`, `@human`, сноски `>`. Выход — один самодостаточный HTML без внешних запросов, с тёмной темой, навигацией и режимом печати. Пример входа — `tools/demo_deck.md`, готовый дек нулевого цикла — `board/`.

Оба скрипта продублированы целиком в `charter/06_DELIVERY.md`, чтобы облачная сессия могла восстановить их из текста. Если правите скрипт — правьте и копию в документе, иначе ночной цикл соберёт дек старой версией.

## 9. Чего не делать

Не оптимизировать метрики средствами, которые запрещает бренд: никаких streak, серий, бейджей, прогресс-баров привычки, напоминаний с чувством вины, обещаний терапевтического эффекта, слов «осознанность», «гармония», «ресурсное состояние», «трансформация», «прокачать», «наш умный алгоритм». Метрика, выросшая за счёт нарушения этого, считается не выросшей — устав §10.

Не расширять сбор данных без ревью InfoSec до постановки задачи в план, а не после. Не давать агентам доступ к содержанию клиентских заметок ни при каких обстоятельствах, включая отладку и аналитику.

Не переоткрывать закрытое: перед внесением предложения проверять `state/12_DECISIONS.md`. Возвращаться к отклонённому можно только с новыми данными и прямой ссылкой на прошлое решение.
