#### H-260813-05 · Снять публичное обещание, которое код не выполняет ⚠️
- **Категория:** публикация / юридическое (решение типа 1)
- **Почему не агент:** текст отдаётся пользователю и входит в юридические документы; изменение публичного обещания и правки в политике конфиденциальности — за человеком, устав §6.1.
- **Что заблокировано без этого:** `B-260813-07` (P0), открытие регистрации внешним пользователям, любая коммуникация маркетинга про приватность ЗАПИСОК.
- **Время учредителя:** 15 минут
- **Срок:** 14.08.2026 · **Приоритет:** блокирует
- **Суть.** Письмо входа и черновик политики утверждают, что мы технически не можем прочитать заметки пользователя. Внутренний аудит в том же репозитории фиксирует обратное: незашифрованная заметка уходит в облако открытым текстом, находка имеет уровень «критический» и статус «блокирует приёмку», регрессионный тест на текущей ветке помечен как заведомо падающий. То есть обещание дано, а механизм не реализован.
- **Как сделать:** утвердить одну из двух формулировок и дать команду разработке заменить текст в письме, в черновике политики и в документации: (а) «шифруется то, что вы зашифровали» — честное описание текущего состояния; (б) снять упоминание шифрования облака полностью до закрытия находки.
- **Рекомендация:** вариант (а) и параллельно закрыть находку до публичного запуска (`B-260813-08`). Цена ошибки: обещание приватности — единственное, что по-настоящему продаёт ЗАПИСКИ помогающему специалисту. Обнаруженное расхождение стоит не штрафа, а профессии — специалист, чья тайна утекла через наш продукт, теряет практику, и восстановить это доверие нельзя ни скидкой, ни релизом.
- **Статус:** открыта

#### H-260813-01 · Перевыпустить токен бота и положить секреты в репозиторий
- **Категория:** доступ
- **Почему не агент:** токен выпускается владельцем бота в @BotFather, а секреты репозитория задаются в интерфейсе GitHub под учётной записью владельца. Ни того, ни другого агент делать не может и не должен.
- **Что заблокировано без этого:** вся доставка — сводки ночного цикла, деки борда, срочные эскалации. Система работает, но её результаты не доходят до вас.
- **Время учредителя:** 10 минут
- **Срок:** 14.08.2026 · **Приоритет:** блокирует
- **Что выяснилось 13.08.** Молчание бота имело две независимые причины, и вторая была не в токене. Первая: сеть облачной среды закрыта списком доменов, `api.telegram.org` в него не входит, запрос к Bot API получает `403` от прокси ещё до Telegram. Вторая: секреты доставки не заданы. Поэтому смена токена сама по себе ничего не чинила — нужен маршрут доставки, который не зависит от сетевых правил среды. Он сделан: отправляет GitHub Actions, у раннера интернет открыт.
- **Как сделать:**
  1. @BotFather → `/mybots` → `@cmpas_board_bot` → API Token → **`/revoke`**. Старый токен попадал в переписку и считается скомпрометированным; `/revoke` выдаёт новый и убивает старый.
  2. Открыть бота в Telegram и написать ему любое сообщение — без входящего сообщения бот не имеет права вам отвечать.
  3. GitHub → `compas-ops` → Settings → Secrets and variables → Actions → New repository secret → `TG_BOT_TOKEN` = новый токен.
  4. Actions → «Telegram · диагностика» → Run workflow. Если `TG_CHAT_ID` ещё не задан, воркфлоу напечатает список чатов бота с их id — скопировать нужный во второй секрет `TG_CHAT_ID` и запустить ещё раз.
  5. Убедиться, что в Telegram пришли проверочное сообщение и PDF.
- **Рекомендация:** держать токен только в секретах репозитория — они шифруются и не видны в логах. Класть его в переменные среды Claude имеет смысл только если решите включить прямую отправку (`09_COWORK §2.3`): там он хранится как обычная настройка среды, а не как секрет. В переписку сессии токен не присылать ни в каком случае — этим путём утёк предыдущий.
- **Статус:** открыта

#### H-260813-02 · Подключить репозитории к рабочей сессии
- **Категория:** доступ
- **Почему не агент:** источники сессии выбирает человек при её создании; прокси выдаёт учётные данные только явно подключённым репозиториям.
- **Что заблокировано без этого:** PO продуктов ПРАКТИКА и МОМЕНТЫ работают вслепую — нулевой цикл это показал наглядно: все настоящие находки пришли из единственного читаемого репозитория.
- **Время учредителя:** 5 минут
- **Срок:** 15.08.2026 · **Приоритет:** блокирует
- **Что выяснилось 13.08.** Причина «среда не видит `compas-ops`» была не в правах: репозиторий был **пуст** — ноль коммитов, ноль веток, нет ветки по умолчанию. Такой репозиторий не отдаёт содержимого никому, включая GitHub API (`409 Git Repository is empty`), и запись в него не с чего начать. Первый коммит эту причину снимает — он сделан.
- **Как сделать:** при создании сессии подключить `compas-psy/compas-ops` с правом записи и `compas-psy/cmpas.ru`, `compas-psy/compas-voice`, `compas-psy/zapiski` на чтение.
- **Рекомендация:** право записи нужно только `compas-ops`; продуктовые репозитории агентам достаточно читать — пуш, мерж и релиз остаются за человеком. Помнить про устройство прокси: агент пушит только свою рабочую ветку и открывает pull request, прямой пуш в `main` невозможен по устройству среды, а не по правам.
