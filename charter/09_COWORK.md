# Возврат ритма в Cowork · настройка среды

Версия 1.0 · 13.08.2026 · владелец документа: COO

Документ решает одну задачу: сделать так, чтобы ночной цикл и борд шли из облачной среды сами и доходили до учредителя. Он нужен, когда среда «не видит репозиторий» или «не может достучаться до Telegram» — оба симптома разобраны здесь до причины.

---

## 1. Что было сломано

Диагностика 13.08.2026. Обе поломки — среда, а не код.

### 1.1. Репозиторий не виден

**Причина: репозиторий `compas-psy/compas-ops` был пуст.** Ни одного коммита, ни одной ветки, нет ветки по умолчанию. Такой репозиторий нельзя ни склонировать во что-то осмысленное, ни прочитать через API: GitHub отвечает `409 Git Repository is empty` на любой запрос содержимого.

Отсюда каскад, который выглядел как отказ доступа: сессия видела репозиторий в списке источников, но получала пустоту, а попытка записи упиралась в отсутствие ветки, от которой можно оттолкнуться.

**Что снимает проблему:** первый коммит с содержимым. После него репозиторий клонируется, читается и принимает записи обычным порядком. Сделано — этой веткой.

Второе, что нужно проверить: репозиторий должен быть подключён к сессии **с правом записи**. Прокси облачной среды выдаёт учётные данные только явно подключённым источникам, и `git push` в такой среде разрешён только в текущую рабочую ветку сессии — в чужую ветку и в `main` пуш не пройдёт по устройству прокси, а не по правам на GitHub. Для ритма этого достаточно: агент пушит свою ветку и открывает pull request.

### 1.2. Telegram недостижим

**Причина: сеть среды закрыта списком доменов, и `api.telegram.org` в него не входит.** Облачные среды Claude пропускают трафик только на разрешённые домены; всё остальное получает отказ на уровне прокси, ещё до адресата.

Проверено прямым запросом из среды агента:

```
urlopen error Tunnel connection failed: 403 Forbidden
```

Это ответ прокси, а не Telegram. Ни токен, ни бот, ни chat_id к этому отказу отношения не имеют — и менять токен ради него бессмысленно. Отличить одно от другого можно за десять секунд: `python3 tools/tg_doctor.py` печатает разные диагнозы для «сеть закрыта», «токен отозван» и «чат не найден».

**Что снимает проблему — два способа, оба рабочие:**

| | Маршрут A · разрешить домен | Маршрут B · через GitHub Actions |
|---|---|---|
| Что настраивается | сетевые правила среды | секреты репозитория |
| Кто отправляет | сам агент, `tools/deliver.py` | воркфлоу `tg-relay.yml` |
| Где лежит токен | переменные окружения среды | секреты репозитория (шифрованы) |
| Шагов у агента | один | два: коммит и запуск воркфлоу |
| Плюс | короче, отправка сразу видна агенту | токен не попадает в среду вовсе |

Маршрут B настраивается обязательно: он не зависит от сетевых правил и остаётся запасным всегда. Маршрут A — по желанию, он делает доставку на шаг короче.

## 2. Что настроить

Три блока, пятнадцать минут. Первый обязателен, второй обязателен, третий по желанию.

### 2.1. Репозиторий

1. Убедиться, что в `compas-psy/compas-ops` есть содержимое (после вливания этой ветки — есть).
2. В сессии Cowork подключить репозитории: `compas-psy/compas-ops` **с правом записи**, а `compas-psy/cmpas.ru`, `compas-psy/zapiski`, `compas-psy/compas-voice` — на чтение.

Право записи нужно только `compas-ops`. Продуктовые репозитории агентам достаточно читать: пуш, мерж и релиз остаются за человеком — устав §6.1.

### 2.2. Секреты Telegram · маршрут B

Токен, который когда-либо попадал в переписку, считается скомпрометированным — его отзывают, а не переиспользуют.

1. **@BotFather → `/mybots` → `@cmpas_board_bot` → API Token → `/revoke`.** Старый токен умирает, выдаётся новый. Все, кто видел старый, теряют доступ к боту.
2. Открыть бота в Telegram и написать ему любое сообщение. Бот не может начать диалог первым: без входящего сообщения он не имеет права вам отвечать.
3. GitHub → репозиторий `compas-ops` → **Settings → Secrets and variables → Actions → New repository secret**:
   - `TG_BOT_TOKEN` — новый токен;
   - `TG_CHAT_ID` — если не знаете, создайте пока только первый секрет: следующий шаг подскажет id.
4. GitHub → **Actions → «Telegram · диагностика» → Run workflow**. Воркфлоу проверит токен и, если `TG_CHAT_ID` не задан, напечатает список чатов бота с их id — останется скопировать нужный в секрет и запустить ещё раз.

Токен в логи не попадает ни при каком исходе: диагностика печатает только имя бота и диагноз.

**Чего не делать:** не присылать токен в переписку сессии, не класть его в документы проекта и в файлы репозитория. Документы проекта видны всем участникам и попадают в контекст каждой сессии — это ровно тот путь, которым утёк предыдущий токен.

### 2.3. Сеть среды · маршрут A, по желанию

Чтобы агент отправлял сам, домену `api.telegram.org` нужно разрешение:

1. [claude.ai/code](https://claude.ai/code) → селектор среды → навести на нужную среду → значок настроек.
2. **Network access** → **Custom**.
3. В поле **Allowed domains** добавить строкой:
   ```
   api.telegram.org
   ```
4. Отметить **Also include default list of common package managers** — иначе среда потеряет доступ к GitHub и реестрам пакетов, и сломается уже всё остальное.
5. Там же, в **Environment variables**, задать в формате `.env`:
   ```
   TG_BOT_TOKEN=...
   TG_CHAT_ID=...
   ```

Про переменные среды нужно понимать одно: они хранятся как настройка среды, а не как секрет, и видны каждому, кто этой средой пользуется. Для личной среды одного учредителя это приемлемо; для общей среды организации — нет, там остаётся только маршрут B.

## 3. Как вернуть задачу Cowork

Ритм переносится промптами из `08_SCHEDULES.md` — они самодостаточны и уже переписаны под репозиторий как память. Порядок:

1. Проверить, что настроено §2.1 и §2.2.
2. Открыть сессию Cowork с подключённым `compas-ops` (запись) и тремя продуктовыми репозиториями (чтение).
3. Поставить два расписания, дословно взяв тексты промптов:
   - ночной цикл — `08_SCHEDULES §1`, cron `0 2 * * *` UTC (05:00 МСК);
   - борд C-1 — `08_SCHEDULES §2`, cron `0 7 * * 1,4` UTC (10:00 МСК).
4. Прогнать один цикл вручную, не дожидаясь ночи, и посмотреть, что дошло.

Если расписания в Cowork уже стоят со старой версией промпта — их нужно заменить целиком, а не дописать. Старый промпт читает память из проекта claude.ai (`project_read` к `claude/ops/...`), которого у новой сессии нет; такой запуск остановится на первом шаге и напишет учредителю, что памяти нет.

Разовое сообщение, которым можно вернуть работу живой сессии Cowork:

```
Ритм ОКОЁМ возвращается тебе. Память системы переехала из проекта claude.ai в
репозиторий compas-psy/compas-ops — он больше не пуст, и права на запись выданы.

Прочитай в нём HANDOFF.md, charter/09_COWORK.md и charter/08_SCHEDULES.md.
Промпты обоих запусков в 08_SCHEDULES переписаны: память — каталоги charter/,
state/, log/ репозитория; ночной цикл теперь тоже собирает дек и присылает
презентацию, а не только текст; доставка идёт командой tools/deliver.py, а если
api.telegram.org в среде закрыт — коммитом артефактов и запуском воркфлоу
«Доставка в Telegram».

Замени оба своих расписания на новые тексты промптов целиком. Затем прогони
ночной цикл вручную и покажи, что дошло до учредителя.
```

## 4. Проверка, что всё работает

По порядку, каждая следующая проверка имеет смысл только после предыдущей.

| Что проверяем | Как | Что должно получиться |
|---|---|---|
| Репозиторий читается | `git clone` в сессии | каталоги `charter/`, `state/`, `tools/` на месте |
| Репозиторий пишется | ветка и пуш из сессии | ветка появилась на GitHub |
| Инструменты целы | `python3 -m py_compile tools/*.py` | тишина |
| Дек собирается | `python3 tools/make_deck.py tools/demo_deck.md -o /tmp/d.html` | HTML собран |
| Презентация собирается | `python3 tools/deck_to_pdf.py /tmp/d.html` | страниц столько же, сколько слайдов |
| Канал жив | `python3 tools/tg_doctor.py --send` | в Telegram пришло сообщение |
| Доставка целиком | Actions → «Telegram · диагностика» → Run workflow | пришли сообщение и PDF |

Последняя строка — единственное настоящее доказательство. Всё, что выше, проверяет части.

## 5. Если бот снова молчит

Сначала диагноз, потом действие. `python3 tools/tg_doctor.py` различает четыре случая, и лечение у них разное:

| Диагноз | Что произошло | Что делать |
|---|---|---|
| `не достучались до api.telegram.org` | сеть среды закрыта | доставлять маршрутом B или разрешить домен (§2.3) |
| `401 Unauthorized` | токен отозван или неверен | новый токен у @BotFather, обновить секрет |
| `chat not found` | учредитель не писал боту, либо id чужой | написать боту, взять свежий id |
| всё зелено, но сообщений нет | доставка не запускалась | смотреть логи Actions: воркфлоу мог не стартовать |

Чего не делать никогда: не искать обходные каналы доставки, не писать учредителю с других адресов, не публиковать дек по внешней ссылке. Канал меняет только учредитель — `06_DELIVERY §7`.

Если канал недоступен два цикла подряд, это перестаёт быть технической неполадкой и становится задачей учредителю по формату устава §6.4. Артефакты при этом не теряются: они уже лежат в репозитории, и доставка добивается позже — `06_DELIVERY §7`.
