# Реестр скилов и инструментов агентов

Версия 1.0 · 15.08.2026 · владелец документа: CTO-агент
Правки — решением борда с пометкой `SKILLS`. Установка новых скилов без записи в этот файл запрещена.

---

## 0. Зачем документ

Скил — это не «дополнительная способность», а постоянный налог на контекст: его описание грузится в каждую сессию, а некоторые ещё и вклиниваются в каждый шаг. Поэтому правило одно: **скил живёт в системе, только если у него есть владелец, зона и ответ на вопрос «что сломается, если его убрать»**.

Три среды, где работают агенты, и они не наследуют скилы друг у друга:

| Среда | Что здесь работает | Кто ставит скилы |
|---|---|---|
| **Раннер** (GitHub Actions) | ночной цикл, борд, распоряжения | шаг установки в workflow |
| **Claude Code** (машина учредителя) | ручная разработка, разбор репозиториев | учредитель, `/plugin` |
| **Облачная сессия** (Cowork) | стратегические сессии с учредителем | скилы аккаунта claude.ai |

Скил, установленный в Claude Code, **не действует** в ночном цикле. Это главная ошибка, которую здесь легко сделать.

## 1. Что установлено и зачем

| Скил | Среда | Зона ответственности | Кто вызывает |
|---|---|---|---|
| **superpowers** | Claude Code | инженерная дисциплина: TDD, систематическая отладка, план перед кодом, ревью | CTO-агент и разработка |
| **impeccable** | Claude Code, облако | фронтенд: вёрстка, визуальная иерархия, доступность, отлов шаблонности | PO-ПРАКТИКА, дизайн |
| **markitdown** | раннер, Claude Code | `.docx/.pdf/.pptx/.xlsx → markdown` перед чтением агентом | любой агент до чтения документа |
| **graphify** | раннер, Claude Code | граф связей по `charter/` и по репозиториям продуктов вместо сплошного чтения файлов | ночной цикл, PO при разборе кода |
| **security-guidance** | Claude Code, раннер | проверка правок на утечки, инъекции, расширение поверхности ПДн | InfoSec-агент, автоматически на правках |

**Отклонены с обоснованием** (не переоткрывать без новых данных, устав §9):

- **supermemory** — внешний SaaS-хранилище памяти. Отклонён: у нас уже есть память (репозиторий), а вынос операционного контекста сервиса для психологов на чужой сервер противоречит §5.4 `CLAUDE.md` и мандату InfoSec.
- **GitHub Spec Kit** — методология spec-driven разработки. Отклонён: прямо конфликтует с процессом планирования superpowers (две несовместимые последовательности «спека → план → задачи»), и рассчитан на команду, а не на одного инженера-агента. Вернуться, когда появится второй разработчик.
- **awesome-claude-skills** — это каталог, а не пакет. Используется как справочник при поиске нового скила, целиком не клонируется: массовая установка скилов раздувает контекст каждой сессии.

## 2. Разграничение зон, чтобы не спорили

Скилы пересекаются на трёх стыках. Правила разрешения:

1. **Планирование.** Планирует один — `superpowers:writing-plans`. Никаких параллельных систем спецификаций.
2. **Ревью безопасности.** Первым идёт `security-guidance` (детерминированные проверки, ноль токенов). `superpowers:requesting-code-review` вызывается только после него и только для логики, а не для секретов — иначе платим дважды за одно и то же.
3. **Чтение чужих документов.** Сначала `markitdown` (конвертация), потом чтение. Агент не читает `.docx` напрямую и не пересказывает его «по названию файла».
4. **Поиск по своим документам.** Сначала `graphify query`, и только если ответа нет — чтение файлов. Сплошное чтение `charter/` целиком допустимо один раз за цикл и только для документов, прямо перечисленных в промпте запуска.

`superpowers:using-superpowers` (требование вызывать скил до любого ответа) в операционных ритмах **выключен**: ночной цикл и борд имеют собственный жёсткий протокол, второй поверх него — чистые накладные расходы.

## 3. Установка

На раннере — шагом в workflow, до запуска агента:

```bash
pip install --break-system-packages 'markitdown[all]'
uv tool install graphifyy && graphify install
```

В Claude Code на машине учредителя:

```
/plugin install superpowers@claude-plugins-official
/plugin install security-guidance@claude-plugins-official
/plugin marketplace add pbakaus/impeccable
uv tool install graphifyy && graphify install
pip install 'markitdown[all]'
```

Проверка после установки: `graphify --version`, `markitdown --help`, в Claude Code — `/plugin` показывает оба плагина включёнными. Пока проверка не пройдена, скил считается неустановленным и в этот файл не вносится.

---

## 4. Правило добавления нового скила

Новый скил вносится борду одной карточкой: что он делает, в какой из трёх сред, чью зону задевает, что сломается без него, и во что обходится по контексту. Без карточки — не ставим. Скил, которым за месяц ни разу не воспользовались, снимается с той же процедурой.
