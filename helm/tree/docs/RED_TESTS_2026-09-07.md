# Семь красных тестов: причина и риск

Разбор по требованию владельца 07.09.2026, п.8: «Семь падающих тестов
нужно однократно классифицировать по причине и риску; фраза „те же семь"
не заменяет этого».

Состояние на `2096be8`, локальный прогон: 1492 зелёных, 7 красных.

## A. Шесть — дыра в самой фикстуре, не в продукте

```
test_knowledge_semantic_v2_registry.py
  test_database_rejects_a_value_outside_the_registry[…]
  test_database_accepts_every_value_of_the_registry[…]
    knowledge_entity_identity_members.matched_on
    knowledge_entity_resolution_candidates.reason
    knowledge_entity_resolution_candidates.status
```

**Причина.** Тест параметризован списком `REGISTRIES`, а SQL для вставки
берёт из словаря `_INSERTS`. Для этих трёх пар (таблица, колонка) записи
в `_INSERTS` нет — тест падает `KeyError` на строке 199, ДО того как
что-либо проверит. Три реестра добавили в параметризацию и не добавили
им INSERT.

**Риск: низкий.** Проверяемые ограничения в схеме есть — заведены
миграциями `a1e7d3c85b40_entity_identity_r6.py` (все три) и
`c9f4b21d78e5_entity_resolution_alias_unconfirmed.py` (переопределение
`reason`). База отвергает значение вне реестра; непроверенной остаётся
только сама проверка. Продуктового поведения это не касается: ни один
путь ответа на вопрос владельца эти таблицы не читает.

**Что нужно.** Дописать три INSERT в `_INSERTS`. Работы на десятки минут,
в очередь после общего цикла памяти.

## B. Один — известное свойство компилятора связей

```
test_knowledge_semantic_v3_publish.py::test_edges_are_typed_and_bound_to_the_run
  assert edges == []
```

**Причина.** Детерминированный компилятор связей (R4.7) выпускает ребро
только при явном доказательстве нужной формы. Фикстура теста такого
доказательства не содержит, и рёбер получается ноль. Это то же самое
`edges=0`, которое разбиралось на реальных источниках (задача R5.4) и
было признано свойством точностного компилятора, а не сбоем.

**Риск: средний, но не для памяти.** Слой связей в ответах владельца
сегодня не участвует: путь ответа идёт по чанкам и памяти. Красный тест
означает, что фикстура не отражает контракт компилятора, — переписывать
надо тест или фикстуру, и делать это осмысленно, вместе с R9.

**Что нужно.** Решается в R9 (KnowledgeGraphify), не раньше: чинить
фикстуру в отрыве от решения про слой связей значит закрепить случайное.

## Итог

Ни один из семи не закрывает и не маскирует дефект пользовательского
пути. Шесть — незаконченная фикстура с низким риском, один — открытый
вопрос слоя связей, привязанный к R9.
