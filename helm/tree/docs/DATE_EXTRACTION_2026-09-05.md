# Даты: схема заработала, гейт съедал атомы

Полный путь: `helm/tree/docs/DATE_EXTRACTION_2026-09-05.md`
Прогон 319 (`recon date-extraction-probe.sh`), 05.09.2026, шесть датонасыщенных окон, 14 минут.

**Пустая временная ось была вызвана схемой, а не слабостью модели.** Владелец нашёл это по коду; замер подтвердил числом.

---

## 1. Что изменено перед замером

`NODE_RESPONSE_SCHEMA` — production-схема constrained decoding. Поля `occurred_at` и `date_precision` в ней **были**, но не входили в `required`. То есть схема официально разрешала модели никогда их не выдавать, и модель этим пользовалась.

Теперь оба поля обязательны, `date_precision` — перечисление `day/month/year/unknown`. Даты нет — `occurred_at` пустой строкой, точность `unknown`.

Заодно ужесточён grounding: раньше он искал в цитате **любую** дату-подобную последовательность, теперь требует **ту же самую** дату с заявленной точностью (`_date_confirmed_by_quote`). Лабораторное «5.4» и номер приказа больше не сходят за подтверждение.

## 2. Четыре числа

| | прогон 319 |
|---|---|
| 1. атомов принято | **7** |
| 2. модель вернула с датой | **45** |
| 3. дат прошло grounding | 7 |
| 4. отклонено date-grounding | **38** |
| — отказ по относительной дате | 0 |
| — отказы по другим причинам | 13 |

**Число 2 — главный результат.** До правки модель дат почти не давала; теперь даёт сорок пять раз на шести окнах. Схема была причиной.

**Число 1 — главная проблема.** Семь атомов на шесть окон. Для сравнения: те же окна в R8 давали по два-три десятка узлов на источник.

## 3. Почему принято всего семь

Непрошедшая дата уносила с собой **весь атом**: в валидаторе стоял `continue`.

Пока модель молчала про даты, этот `continue` почти не срабатывал. Как только поля стали обязательными, он стал основным исходом — и начал выбрасывать знание вместе с недоказанной датой. «Креатинин 111 при норме 59–104» — факт, который не перестаёт быть фактом оттого, что модель приписала ему дату из шапки документа.

Исправлено: дата снимается, атом остаётся, отказ по-прежнему записан. Grounding при этом **не ослаблен** — неподтверждённая дата в граф не попадает как не попадала. Тот же принцип уже стоял строкой выше про точность вне реестра: «не повод терять весь атом».

## 4. Вторая находка: `occurred_at = "unknown"`

Промпт просит при отсутствии даты оставить поле пустым. Модель пишет туда слово `unknown`.

В базе это безобидно: `parse_occurred_at()` такую строку не разбирает и оставляет NULL. Но в любом замере она читается как «дата есть» — из семи «прошедших grounding» атомов прогона 319 часть именно такие. Число 3 в таблице выше поэтому завышено; на сколько именно, скажет повторный замер.

Исправлено: `occurred_at` принимается только в разбираемой форме `YYYY`, `YYYY-MM`, `YYYY-MM-DD`.

## 5. Открытый вопрос: даты живут в шапке, evidence — в строке таблицы

Три из пяти примеров прогона прошли grounding так:

```
Серологические исследования → 2023-10-08 (day)
    → «№ направления: 137703425 Дата: 08.10.2023»
```

Дата и цитата совпали, потому что цитатой оказалась сама строка шапки. А вот это не прошло и пройти не могло:

```
Креатинин → (дата снята)
    → «Креатинин | | ↑ | 111 | мкмоль/л | 59-104 |»
```

Дата анализа стоит в шапке документа один раз и относится ко всем строкам таблицы. Правило «дата обязана быть в собственной цитате атома» для такого документа невыполнимо в принципе.

Три варианта, решение за владельцем:

1. **Оставить как есть.** Дата будет только у тех атомов, чья собственная цитата её содержит. Для выписок и заключений это работает, для лабораторных таблиц — нет.
2. **Подтверждать по тексту окна, а не только по цитате атома.** Слабее: в окне может быть несколько дат, и атом получит не свою.
3. **Дата документа отдельным полем**, не датой атома. Честнее всего структурно: «этот анализ сдан 08.10.2023» — свойство источника, а не каждой его строки. Дороже: нужна новая колонка и правило наследования.

Я за третий, но это не тот выбор, который агент делает молча.

## 6. Чего замер НЕ говорит

Он сделан на шести окнах одного домена (health) и почти целиком на лабораторных бланках — тот самый тип документа, где дата в шапке. На выписке или заключении расклад будет другим. Переносить 38/45 на весь корпус нельзя.
