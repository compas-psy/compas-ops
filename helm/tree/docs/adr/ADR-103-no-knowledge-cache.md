# ADR-103. Кэш готовых ответов Второго мозга не делается

**Дата:** 30.08.2026 · **Статус:** принято учредителем, область уточнена
им же в тот же день · **Пересмотр:** по условию ниже

## Область решения

Решение ровно одно и очень узкое:

```text
Knowledge application-level answer cache = OFF by default
                                          = не входит в DoD v1
```

Речь о кэше **готовых ответов** HELM Knowledge. Ничего другого это
решение не касается и не отменяет. Глобального `cache=false` по HELM нет
и быть не должно.

## Что сохраняется — перечислено, чтобы не «оптимизировали» по ошибке

| Уровень | Состояние | Зачем |
|---|---|---|
| Кэш PostgreSQL и страничный кэш ОС | сохраняется | естественный инфраструктурный кэш, никто его не трогает |
| Индексы: FTS, pgvector, embeddings | **обязательно сохраняются** | это индексы знания, а не кэш ответов. Их отсутствие ломает сам поиск |
| `keep_alive` у Ollama | сохраняется | держит локальную модель в памяти, иначе каждый локальный ответ платит за загрузку |
| Кэширование LiteLLM | **не удалять**; сейчас в `config/models/litellm.yaml` не настроено ни в какую сторону | это оптимизация стоимости платного контура, отдельная от Второго мозга. Включение — самостоятельная задача экономии, а не часть этого решения |
| Prompt caching провайдера | использовать там, где модель и OpenRouter реально его поддерживают | прямая экономия на платных вызовах |
| Кэш внешних API и интеграций | решается отдельно для каждой | у каждой свои гарантии свежести |
| Статический HTTP-кэш панели | сохраняется там, где безопасно | обычная отдача статики |

Ключевое различие в одну строку:

```text
ВТОРОЙ МОЗГ        свежая выборка на каждый запрос, готовых ответов не кэшируем
ПЛАТНЫЙ КОНТУР     Hermes → LiteLLM → OpenRouter, кэширование не трогаем
```

## Как читается §14.17

Раздел ТЗ называется «Cache» и перечисляет десять полей ключа и восемь
событий сброса. Он не требует завести кэш — он ставит условия **на кэш,
если тот есть**. Прочтение «нужно сделать кэш» — это чтение заголовка
вместо текста.

Эти требования сохраняются как **будущий контракт**: если телеметрия
когда-нибудь докажет нужду в кэше ответов, он делается по §14.17
целиком, со всеми десятью полями ключа и всеми восемью триггерами.

## Почему кэша ответов нет сейчас

**Он ничего не экономит в деньгах.** Путь знания устроен так:

```text
запрос → выборка в границах пользователя
       → PostgreSQL FTS / pgvector / связи / Graphify
       → детерминированный ответ или локальная Ollama
       → ответ
```

При `KNOWLEDGE_HIT` действует `paid_model_allowed = false`. OpenRouter в
этом пути не вызывается вообще. Значит отсутствие кэша готовых ответов
**не увеличивает расход на OpenRouter ни на копейку** — экономить там
нечего, потому что там ничего и не тратится.

**Он ничего не экономит во времени.** Сегодня поиск — один
индексированный запрос к Postgres, миллисекунды.

**Он создаёт риск ровно там, где его быть не должно.** Разделение между
людьми требует `knowledge_user_id` в каждом ключе и срабатывания каждого
из восьми триггеров сброса. Забытый триггер означает, что второй человек
получит ответ первого, а забытое поле ключа — что человек получит
устаревшее знание после того, как сам его исправил. Это худшие отказы в
системе, и в тестах они невидимы, пока в них не целятся специально.

**Без него §14.17 выполняется доказуемо.** Устаревшее или удалённое
знание отдать неоткуда: каждый ответ собирается из базы в момент
вопроса. Требование §36 «удалённое знание не утекает через кэш»
удовлетворено отсутствием места, где оно могло бы залежаться.

## Чего не добавлять сейчас

```text
Redis ради кэша ответов Knowledge
отдельная таблица кэша ответов
сохранённые финальные ответы Второго мозга
```

## Когда пересмотреть

После P8.5.4 (смысловой поиск на embeddings) и P8.5.5 (локальный
генератор Z2) путь ответа станет «эмбеддинг запроса → векторный поиск →
генерация на CPU». Это уже секунды.

**Порог:** повторный одинаковый вопрос стабильно дольше двух секунд по
данным телеметрии. Тогда — кэш по §14.17 целиком, с отдельным тестом на
каждый триггер сброса.

## Итог для записи

```text
Кэш ответов Knowledge:      ВЫКЛЮЧЕН
                            причина: пользы мало, риск устаревания и
                            пересечения между людьми велик

Кэш LiteLLM и облачный:     НЕ ТРОГАЕМ
                            фактически: в конфиге не настроен вовсе,
                            то есть работает умолчание LiteLLM
                            причина: экономия на платном выводе — своя
                            задача, к §14.17 отношения не имеет

Ollama keep_alive:          СОХРАНЯЕТСЯ
                            причина: задержка локального ответа

Кэш PostgreSQL и индексы:   СОХРАНЯЮТСЯ
```

## Честно о состоянии платного кэша

«Сохраняется» здесь означает «не трогаем», а не «включено». На
30.08.2026 в `config/models/litellm.yaml` нет ни включателя, ни
выключателя кэша — работает умолчание LiteLLM. Настройка кэширования
платного контура и prompt caching провайдера остаётся отдельной задачей
экономии, и решение по §14.17 её не отменяет и не приближает.

Чтобы это решение не расползлось, поставлен сторож:
`test_knowledge_cache_decision_did_not_disable_the_paid_path_cache`
роняет прогон, если в конфиге LiteLLM появится явный выключатель кэша.

## Что проверяется регрессией

```text
Запрос к знанию без явного обращения к ИИ
    → 0 вызовов LiteLLM
    → 0 вызовов OpenRouter

Обычный платный запрос
    → штатный путь LiteLLM/OpenRouter
    → возможность облачного кэширования сохранена
```

Чем закрыто:

| Утверждение | Тест |
|---|---|
| Путь составления ответа не может дозвониться до модели | `test_knowledge_answer_composition_cannot_reach_a_model_or_owner_style` — разбор по AST: модули `probe`, `recall`, `memory` не импортируют ни `litellm`, ни `openai`, ни `openrouter`, ни сетевой клиент. Позвать модель оттуда нельзя, не переписав файл |
| Ответ из памяти не считается платным | `test_recall_makes_zero_paid_calls` — `paid_ai_used = false` в записи ответа |
| Решение §14.17 не выключило кэш платного контура | `test_knowledge_cache_decision_did_not_disable_the_paid_path_cache` |
