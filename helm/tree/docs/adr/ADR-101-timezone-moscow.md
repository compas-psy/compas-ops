# ADR-101. Часовой пояс сервера: Europe/Moscow вместо Europe/Helsinki

**Дата:** 27.08.2026 · **Статус:** принято по прямому распоряжению учредителя

## Контекст

ТЗ §4.1 задаёт `Europe/Helsinki` как часовой пояс owner-facing расписаний
(морнинг-брифы, дайджесты D4: 07:30/09:00/18:00). Это значение по умолчанию,
выбранное автором спеки без дальнейшего уточнения от фактического
местоположения владельца.

## Решение

Учредитель, будучи автором самой спеки, дал прямое распоряжение в реальном
времени: `Europe/Moscow`. Это не расхождение в трактовке, а исправление
факта — owner-facing время должно совпадать с реальным часовым поясом
владельца, а не с тем, что было вписано в документ по умолчанию.

## Последствия

Меняется:
- системный TZ сервера (`timedatectl set-timezone Europe/Moscow`, P1)
- время морнинг-брифов и дайджестов D4 остаётся **07:30 / 09:00 / 18:00**,
  но теперь по московскому времени, не хельсинкскому (разница 1 час)
- `Guardian forecast`, `restic` retention windows и подобные TZ-агностичные
  величины не затрагиваются

Это правится один раз здесь; последующие фазы (P4 Hermes cron, P27
Autonomous routines) читают TZ из системной настройки сервера, а не
хардкодят `Europe/Helsinki` заново.
