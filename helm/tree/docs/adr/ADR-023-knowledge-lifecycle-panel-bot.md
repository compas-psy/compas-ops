# ADR-023. Knowledge lifecycle management Panel/bot

**Дата:** 31.08.2026 · **Статус:** частично реализовано — lifecycle
памяти через бота сделан и живьём подтверждён; lifecycle документов
через бота и любой lifecycle через Panel — не реализованы, не входят в
объём этого ADR как «сделано».

## Контекст

§14.16 описывает управление уже сохранённым знанием словами — не только
запись, но и «забыть», «вернуть», «удалить навсегда», «исправить».
Вопрос — на каких поверхностях (бот, Panel) и для каких сущностей
(память, документы) это реализовано.

## Решение

**Lifecycle Micro-Memory через бота — сделано, тот же движок для обеих
ролей.**

`helm_core/knowledge/admin.py` (§14.16, `docs/KNOWLEDGE_ADMIN.md`) —
ноль платного AI на каждом шаге: разбор команды — регулярные выражения,
поиск цели — полнотекстовый поиск PostgreSQL, решение — сравнение
чисел. Команды: `Забудь`/`Не используй` (обратимо, статус `DISABLED`),
`Верни в память`/`Восстанови` (обратимо, назад в `ACTIVE`), `Удали
навсегда` (**необратимо**, физическое удаление), `Исправь ... : ...`
(текст записи заменяется, сама запись остаётся той же). Разрешение
цели: одно совпадение — действуем и показываем текст; несколько —
перечисляем, просим уточнить; ноль — так и отвечаем. Уточняющего
диалога с состоянием нет: для действий, половина которых необратима,
переспросить безопаснее, чем угадать.

Работает одинаково у владельца (Telegram/MAX) и у KNOWLEDGE_USER
(Dedicated Knowledge Bot) — единственная разница: каждый видит и меняет
только своё (RLS, ADR-030).

## Не в объёме этого захода — явно, не тихо

- **Команды над документами** (`KnowledgeSource`, не `KnowledgeMemory`):
  «Переразбери», «Перенеси в …», «Обнови граф» из §14.16 не реализованы.
  Поиск источника по имени для них уже есть (`documents.py`) — не
  хватает самих команд-глаголов.
- **Любой lifecycle через Panel**: `api/panel.py` даёт только чтение —
  список памяти/источников, поиск, скачивание оригинала (passkey-гейт).
  Ни одного мутирующего эндпоинта для памяти/документов (забыть/вернуть/
  удалить/исправить) нет — только account-level действия (suspend/
  reactivate/квота/удаление пользователя/экспорт архива). Явно
  зафиксировано отдельно: «редактирование/удаление памяти и документов
  из панели... не реализован ни для одной роли» — это не найденный
  сейчас пробел, а уже известное, названное ограничение текущего Panel-
  среза (P8.6.5).

Причины отсрочки для обеих веток не оформлены отдельным owner-решением
(в отличие, например, от версионирования источников, ADR-022) — читаются
как «ещё не дошли», не как сознательный вырез объёма.
