# ADR-017. Первичное развёртывание: офлайн-сборка вместо live-server-first

**Дата:** 27.08.2026 · **Статус:** принято · **Заменяет:** ничего

## Контекст

ТЗ §31.0 требует live-server-first: агент подключается по SSH и правит
`/opt/helm` прямо на VPS. Формулировка запрета точная:

> Нельзя отвечать владельцу патчем/репозиторием вместо фактической установки,
> **если SSH доступ работает.**

В среде реализации SSH не работает и не может быть открыт изнутри:

| Проверка | Результат |
|---|---|
| `nc -vz 185.250.44.137 22` | timeout, rc=124 |
| CONNECT 185.250.44.137:443 через egress-прокси | `403 — policy denial` |
| SSH-клиент | не установлен |
| Альтернативные среды (`list_environments`) | обе `anthropic_cloud`, та же политика |

README прокси прямо запрещает обходить отказ политики: «не ретраить, не
обходить, сообщить о заблокированном хосте».

## Решение

Условие запрета не выполнено, поэтому применяется абзац §31.0 об
ограниченной среде: ограничение фиксируется, всё, что не требует сервера,
собирается офлайн, живые фазы исполняются из среды с доступом.

Дерево `helm/tree/` в `compas-ops` отображается на `/opt/helm` один в один.
Развёртывание — копирование дерева и запуск, а не «применение патчей».

## Последствия

**Хорошо.** Ядро Control Plane, Guardian, панель, policy и тесты проверены
против настоящего PostgreSQL 16 и настоящего Chromium ещё до первого
подключения к VPS. Ошибка вроде «миграция не совпадает с моделями» найдена
здесь, а не на сервере в P2.

**Плохо.** Git на этом этапе выполняет роль транспорта, чего §31.0 не хотел.
Смягчение: Git здесь не гейт и не механизм отката — откат обеспечивает
`scripts/checkpoint.sh` на сервере, как и требует §31.0. Как только появится
среда с SSH, дальнейшая работа идёт по live-server-first без изменений в
архитектуре.

**Чего это не отменяет.** P0–P15 по-прежнему исполняются на VPS. Офлайн-сборка
сокращает P2, P5 и P7.5, но не заменяет ни одной фазы: preflight, хост,
LiteLLM, Hermes, бэкапы и приёмка требуют живого сервера.
