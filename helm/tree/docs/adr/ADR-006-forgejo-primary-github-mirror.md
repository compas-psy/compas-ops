# ADR-006. Forgejo primary / GitHub mirror+CI

**Дата:** 31.08.2026 · **Статус:** целевая архитектура и миграционный
план решены и написаны; сама миграция репозиториев НЕ выполнена
(`MIGRATION-LOG.md`: шаги 2-11 не выполнены, готов только шаг 1 —
инвентаризация).

## Контекст

Forgejo — самостоятельный self-hosted git на том же VPS
(`git.cmpas.ru`), заведён живьём 29.08.2026 как сервис. Вопрос: что
происходит с существующими репозиториями на GitHub и в каком статусе
каждый git-хостинг остаётся после переезда.

## Решение

**Forgejo становится primary, GitHub — push-mirror для CI, переключение
— по одному репозиторию, отдельным решением владельца на каждый.**

`scripts/forgejo-migrate-runbook.md`/`forgejo-migrate.py` реализуют
именно эту целевую схему: репозиторий копируется в Forgejo, дальше
Forgejo → GitHub идёт push-mirror («Правило заморозки»: с момента
миграции GitHub-копия мигрированных репозиториев — только зеркало, не
второй источник правды), CI проверяется на зеркалированном SHA (§18.5)
ДО переключения.

Явно зафиксированный порядок: «Шаг 11, переключение primary remote —
только после PASS CI-пробы, отдельным решением владельца, по одному
репозиторию» — не одномоментный переезд всех репозиториев разом.

Forgejo — приватный по умолчанию, регистрация отключена
(`docker-compose.yml`).

## Не в объёме этого захода — выполнение, не только план

`MIGRATION-LOG.md` (29.08.2026): «Шаги 2–11. Не выполнены» — сделан
только шаг 1 (инвентаризация репозиториев). Ни один реальный репозиторий
не скопирован в Forgejo, ни один push-mirror не настроен, ни одно CI не
проверено на зеркале, ни один primary remote не переключён. С момента
последней записи в `MIGRATION-LOG.md` (29.08.2026) до сегодняшнего дня
изменений не было.

Открытые под-решения, названные в `MIGRATION-LOG.md`, но не закрытые —
не блокируют этот ADR, но требуют отдельного владельческого решения
перед выполнением: default-branch для `zapiski`/`signalAI-mobileApp`
(агентская ветка против `main`), обрезка ~309 старых веток, и особая
роль GitHub Issues как командной панели у `signalAI-mobileApp`
(workflow'ы на `issue_comment`) — для него зеркалирование может
потребовать отдельного решения, не общего со всеми остальными
репозиториями.

`charter/07_REPOS.md` (последняя проверка 13.08.2026, до заведения
Forgejo) не упоминает Forgejo вовсе — устарел относительно этого
решения, к сверке при следующей ревизии устава.

## Не в объёме этого захода

- Собственно выполнение миграции (шаги 2-11) — план готов, исполнение
  не начато.
- Обрезка старых веток, финальный выбор default-branch на репозиторий,
  особый режим для `signalAI-mobileApp`.
