# ADR-020. Strict zero-paid Knowledge lock

**Дата:** 31.08.2026 · **Статус:** реализовано как структурная гарантия
(не рантайм-проверка), подтверждено AST-тестами и живым деплоем.

## Контекст

§14.1 требует, чтобы KNOWLEDGE_USER (секондари-пользователь Second
Brain) по умолчанию не мог дойти до платной модели вообще — не как
предпочтение, а как жёсткий гейт.

## Решение

**Гарантия — импорт-изоляция, проверяемая по AST, не флаг, который
код обязан не забыть проверить.**

`KnowledgeUser.allow_paid_ai: bool = False` по умолчанию существует в
схеме, но НЕ читается нигде в рантайм-логике (грепом по `helm_core`
поле встречается только в определении, в `GET /api/panel/v1/users` для
отображения и в одном тестовом assert дефолта) — это не недоделка, а
следствие того, что гарантия реализована СИЛЬНЕЕ, чем поле могло бы
дать: не условная проверка, а структурная невозможность.

### AST-тесты, не строковый поиск

`tests/test_api.py::_imported_modules()` парсит AST файла, не ищет
подстроку — комментарий, упоминающий "litellm", не даст ложного
срабатывания. `FORBIDDEN_MODEL_CLIENTS` — множество запрещённых
клиентов (litellm/openai/anthropic/openrouter/hermes/chief). Три теста
проверяют три разных модуля:

- `test_panel_module_cannot_call_a_model` — `panel.py` не импортирует
  модельный/сетевой клиент вообще.
- `test_knowledge_answer_composition_cannot_reach_a_model_or_owner_style`
  — `probe.py`/`recall.py`/`memory.py` (модули, которые СОБИРАЮТ ответ)
  не импортируют ни один из `FORBIDDEN_MODEL_CLIENTS`.
- `test_knowledge_user_webhook_cannot_reach_a_model` — вебхук
  Dedicated Knowledge Bot (`hooks_knowledge_telegram.py`) не
  импортирует модельный клиент (сетевой клиент для скачивания файла —
  разрешён отдельно).

ADR-029 формулирует итог дословно: «KNOWLEDGE_USER не может дойти до
Hermes/OpenRouter/LiteLLM НЕ ПОТОМУ, ЧТО рантайм-проверка это
запрещает, а потому, что этот модуль их попросту не импортирует —
"never reaches Hermes by construction" в буквальном, не переносном
смысле». `V3.8-DELTA.md` подтверждает как уже сделанное: «Styles never
cross users» и «paid AI forbidden by default for KNOWLEDGE_USER» — по
конструкции, а не проверкой в рантайме.

### Метрика — фиксирует эскалацию, не предотвращает её

`KnowledgeAnswerRun.paid_ai_used` (§14.14) выставляется в трёх местах,
все на владельческих путях: `probe.py` (`False` для локальных ответов),
`api/hooks.py`/`api/internal.py` (`True` на реальную эскалацию к
Hermes) — метрика наблюдает, но сама гарантия для KNOWLEDGE_USER не
зависит от того, что кто-то посмотрел на неё постфактум.

### Отклонение от исходной формулировки спеки

Спека, по всей видимости, изначально предполагала «zero-paid router» —
условный компонент, решающий по флагу. Это явно выведено из области
работы v3.7 ("zero-paid router и остальные 10 подпунктов P8.5 v3.7" —
не в объёме той поставки). То, что построено — импорт-изоляция —
сильнее и не требует, чтобы роутер каждый раз правильно проверил флаг;
это задокументированное отклонение от буквы спеки в сторону более
жёсткой гарантии, не пропуск.

## Не в объёме этого захода

- `allow_paid_ai=True` как реальный путь эскалации для KNOWLEDGE_USER
  (поле существует, но структурно не может быть использовано сегодня —
  потребует отдельного модуля, который явно импортирует модельный
  клиент, минуя нынешнюю AST-гарантию для остальных модулей).
- Владелец (`SYSTEM_OWNER`) этим гейтом не ограничен — гарантия
  специфична для secondary-пути.
