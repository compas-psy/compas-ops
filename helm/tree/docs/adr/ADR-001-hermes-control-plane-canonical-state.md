# ADR-001. Hermes cognitive / Control Plane canonical state

**Дата:** 31.08.2026 · **Статус:** реализовано и живьём подтверждено —
принцип пронизывает уже задеплоенный код (ADR-012, ADR-014, MAX/Telegram
пути), но нигде не был сформулирован как отдельное решение до этого
документа.

## Контекст

С несколькими входами (Telegram, MAX) и двумя разными системами
(Control Plane — FastAPI/Postgres, Hermes — плагинный когнитивный
раннер) нужен явный ответ: кто хранит правду о том, что произошло, и
кто решает, что делать дальше. Без этого легко получить два источника
истины, которые расходятся.

## Решение

**Раздел по типу состояния, не «один хозяин на всё».**

### Control Plane — canonical для идентичности, дедупа, задач, approval

`api/hooks.py` (docstring, §10.1 дословно): «проверить секрет →
проверить владельца → дедуплицировать → зарегистрировать task →
Knowledge Probe → вызвать локальный chief API». Вердикт дедупликации
нужен ДО обращения к Hermes — на схлопнутом дубле chief не должен
отвечать во второй раз на уже отвеченный вопрос.

`hermes/plugins/helm-control/__init__.py`: `pre_gateway_dispatch`
регистрирует входящее сообщение в Control Plane ДО того, как оно дойдёт
до LLM — «если Control Plane не подтверждает регистрацию... сообщение
до модели не доходит: это fail-closed по конструкции».

ADR-012 (durable execution) — Postgres-машина состояний approval/action
(`ApprovalStatus`, `execute_approved`, идемпотентность) — единственный
durable источник правды о том, какие действия реально произошли.

ADR-014 подводит итог прямо: «всей маршрутизацией (кто спросил, куда
отвечать) занимается Control Plane, как и предписывает §10.1» — три
альтернативных дизайна MAX-канала отклонены именно потому, что все они
«делают Hermes владельцем канала MAX».

### Hermes — canonical для разговорного контекста конкретной сессии

`hermes_bridge.py` (§10.2 буквально): вызов Control Plane→Hermes несёt
только имя `conversation`, сервер сам резолвит его в
`previous_response_id` последнего ответа — «ничего, кроме имени,
Control Plane не хранит; multi-turn context живёт целиком внутри
Hermes ("без хранения полного MAX transcript в Control Plane")». Это не
пробел, а сознательная граница: Control Plane не дублирует то, что
Hermes и так обязан помнить как раннер диалога.

### Итог — не «Control Plane побеждает всегда»

Правильная формулировка: Control Plane canonical для того, ЧТО решено и
КОМУ отвечать (identity/dedup/задачи/approval-состояние — переживает
рестарт Hermes, переживает смену модели); Hermes canonical для того, О
ЧЁМ говорили в рамках одной сессии (переживает рестарт Control Plane
ровно потому, что и не должно храниться нигде ещё). См. также ADR-004
(состояние Hermes само по себе не считается durable-источником для
Control Plane).

## Не в объёме этого захода

- Явная сверка/детект расхождения между двумя состояниями (например,
  Hermes «думает», что диалог продолжается, а Control Plane уже считает
  задачу закрытой) — механизма обнаружения такого рассинхрона нет.
