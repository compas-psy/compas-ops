# ADR-015. HELM Panel static frontend + Control Plane backend

**Дата:** 31.08.2026 · **Статус:** реализовано, задеплоено, живьём
подтверждено («панель с passkey» — Milestone B "Работает",
`ROADMAP-TO-DONE.md`).

## Контекст

§10.5.2/§10.5.3/§7.3 описывают Panel как отдельный веб-интерфейс
владельца (и, начиная с v3.8, второго пользователя) поверх того же
Control Plane, которым уже пользуются Telegram/MAX.

## Решение

**Статическая сборка, ноль Node-процесса в проде; вся логика — в уже
существующем FastAPI-бэкенде, не в новом сервисе.**

### Frontend — React + TypeScript + Vite, статика

`panel/README.md`: «Production-фронтенд пульта. React + TypeScript +
Vite, сборка в статику — в проде node-процесса нет (ТЗ §10.5.2), файлы
отдаёт Caddy.» Структура — `src/{App.tsx,Login.tsx,components,sections,
api,styles}`, собранный бандл — `dist/`.

`docker-compose.yml`: `caddy` монтирует `panel/dist:/srv/panel:ro`
read-only — единственный артефакт, который попадает на сервер из
Panel-репозитория, никакой Node/Vite процесс не поднимается и не может
быть скомпрометирован в рантайме.

`config/Caddyfile` (§10.5.2/§10.5.3): `/api/panel/v1/*` и `/auth/*` идут
`reverse_proxy 127.0.0.1:8080` (Control Plane), всё остальное отдаётся
статикой из `/srv/panel` с `try_files {path} /index.html` (SPA fallback).

### Backend — тот же Control Plane, не отдельный сервис

`api/panel.py` (docstring, ТЗ §7.3/§10.5.5): «Железное правило раздела:
**GET не запускает LLM**. Все ответы собираются из сохранённого
состояния... в модуле нет ни одного импорта модельного клиента —
нарушить правило нельзя случайно, только переписав файл.» Проверяется
тестом §30.7 на уровне AST — не полагаемся на дисциплину код-ревью,
нарушение физически не компилируется в проходящий тест.

«Панель также не имеет собственной логики побочных эффектов (§7.3):
write-эндпоинты вызывают тот же action registry и тот же approval
engine, что и Telegram» — Panel не второй источник правды и не второй
путь исполнения действий, только другой транспорт для тех же вызовов.

## Не в объёме этого захода

- Собственный SSR/сервер для Panel — сознательно не строится, статика
  отдаётся Caddy.
- ADR-025 (hybrid retrieval) Panel не касается — единственная
  оставшаяся связь Panel↔Knowledge на сегодня узкая: счётчики записей
  (P8.6.5), не полноценный UI управления базой знаний (см. тему 023,
  ADR не написан).
