# ADR-027. Micro-Memory «Запомни» fast path

**Дата:** 31.08.2026 · **Статус:** реализовано, задеплоено v3.8 Фаза 1,
живая функциональная проверка (реальное «Запомни» через бота) —
отдельный пункт, ещё не пройден (см. ROADMAP-TO-DONE.md п.26).

Решение принято и код написан 30.08.2026 (v3.8 Фаза 1); документ здесь
задним числом фиксирует уже реализованное — то самое расхождение
«не написан ≠ не принято», которое и завело этот ADR-реестр
(`docs/adr/README.md`).

## Контекст

§14.10-14.11 (P8.5.12) описывают отдельный, лёгкий путь для команды
«Запомни»: короткий факт, ссылка или заметка не должны идти через полный
document-pipeline (MarkItDown/Docling/чанкинг/embeddings) — это
избыточно и медленно для одной строки текста, которую владелец хочет
сохранить мгновенно, не дожидаясь асинхронного разбора.

## Решение

**Прямой FTS-юнит, ноль LLM.** `helm_core/knowledge/memory.py::
try_remember()` — детерминированная классификация БЕЗ Ollama structured
classifier (тот же остаток П8.5.6, что уже задокументирован в
`V3.8-DELTA.md` — не блокирует Micro-Memory, просто not yet built):
regex-префиксы (`Запомни`/`/remember`/`Сохрани в память`/`Не забудь`),
никакого свободного NLU.

Ключевые упрощения против буквы спеки, сделанные осознанно (не пропуск,
см. докстринг `memory.py`):

- **`kind`** — только `bookmark` (в основном URL) или `note` (всё
  остальное); `fact`/`identifier`/`preference`/`temporary` из спеки не
  различаются классификатором. Спека сама разрешает: "kind optimizes
  rendering/retrieval; canonical_text+payload_json remain flexible" —
  сузить enum можно позже, без потери данных задним числом.
- **`domain` всегда `None`.** Спека прямо требует: "retrieval remains
  global so this never hides memory" — эвристика "high-confidence local
  match" не строится (то же решение, что уже принято для L1 SOURCE
  domain в v3.7 до реестра доменов).
- **Порог 8 000 символов** (`§14.10 "default starting point 8,000
  chars"`) — за этим порогом текст уходит в обычный `ingest_text()` как
  SOURCE, не остаётся одним memory-объектом.
- **Temporal parsing** — только "сегодня"/"завтра" (конец локальных
  суток, `Europe/Moscow`, ADR-101). Полноценный NLU-парсер дат не
  строится: "Do not invent expiry without an explicit temporal marker"
  (§14.10) — без явного маркера memory просто не истекает.
- **Секреты не сохраняются.** §14.10 "forbidden secret text is not
  written to normal DB" — распознанный секрет (пароль, ключ) не создаёт
  memory-запись вовсе, а не сохраняется замаскированным.
- **Точный повтор — не вторая активная запись** (§14.10 "Exact repeat →
  no second active item") — дедуп по `dedup_hash`
  (`ix_knowledge_memories_user_dedup`), не ошибка, штатное поведение.

### Таблица и место в схеме

`knowledge_memories` (миграция `ef1ba5467e14`, та же, что и вся v3.8
tenancy-схема) — tenant-scoped (RLS, `4da8c9e90115`), с колонками
`status`/`origin_channel`/`origin_message_id`/`origin_kind`/
`graph_status="not_applicable"` (Graphify не реализован, P8.5.6 —
тот же принцип, что и у `KnowledgeBatchItem.graph_status`). Индексы —
`(knowledge_user_id, status)` и `(knowledge_user_id, dedup_hash)`, плюс
GIN на `tsv` для полнотекстового поиска.

### Голос — явный, задокументированный пробел, не эта функция

GigaAM нигде не подключён к этому модулю: `try_remember()` работает
только с готовым текстом. Путь "voice → GigaAM → transcript → тот же
Remember-путь" реализован ОТДЕЛЬНО в ADR-021 фазе 2b
(`worker.py::process_voice_pending()`), который вызывает `try_remember()`
уже с расшифрованным текстом — не дублирует логику классификации.

### Recall — читающая половина, реализована отдельным модулем

`recall.py` (§14.12-14.13) — `try_remember()` пишет, `recall.py` читает,
встроено в обычный `probe()` на каждый вопрос, общего состояния кроме
таблицы у них нет. Ноль LLM: детекция намерения — регулярки, поиск —
PostgreSQL FTS, композиция ответа — конкатенация (§14.14 "protected
exact data must never be rewritten" выполняется не проверкой, а
конструкцией — переписывать текст нечем). Попадание в память имеет
АБСОЛЮТНЫЙ приоритет над document-чанками — не откалиброванный вес
(golden-набора для калибровки нет, §30.8.5), а самый сильный из
возможных boost, при этом детерминированный. Из семи намерений §14.13
реально разведены только два (RECALL_MEMORY vs "напоминание" —
DOCUMENT_REQUEST/KNOWLEDGE_ADMIN/LIVE_EXTERNAL не имеют реализации, за
них разводить нечего); уточняющий диалог при неоднозначности не
реализован — детектор напоминания требует совпадения трёх признаков
сразу, чтобы неоднозначное сообщение падало в recall, а не терялось.

## Не в объёме этого захода

- Reply/forwarded-text как источник payload'а ("Запомни это" в ответ на
  сообщение) — ни один канал (MAX/Telegram) сегодня не передаёт в HELM
  Core текст, на который ответили.
- URL canonicalization (снятие tracking-параметров) — `original_url`
  хранится как есть.
- `KnowledgeMemory.last_used_at` — recall'ом не обновляется, ранжирования
  по нему нет.
