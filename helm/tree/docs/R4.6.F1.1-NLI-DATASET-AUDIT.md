# R4.6.F1.1 — offline audit F1 dataset v1 vs v2

Владелец 03.09.2026: run 233 (R4.6.F1d) остаётся валидным результатом
только для F1 dataset **v1**, не доказательством, что local NLI approach
исчерпан. Найден фундаментальный дефект v1: `NliExample.hypothesis`
строился подстановкой `GoldAtom.canonical_text` (целого предложения) в
шаблон вида `"{a} участвует в {b}."`, как будто это именная группа.

Этот документ — полный OFFLINE audit (ни одного вызова NLI/Ollama),
произведённый `scripts/r4-f1-1-offline-audit.py` на реальных golden
fixtures. Verbalizer v2 — `helm_core/knowledge/relation_verbalizer_v2.py`
(11 тестов, `tests/test_knowledge_relation_verbalizer_v2.py`).

Сырой вывод скрипта воспроизведён ниже целиком (owner: "для каждого
вывести..." — построчно, не пересказом).

явному правилу владельца "не притворяться, что статистика надёжна".

## Ключевые находки

1. **36 из 37 v1 hypothesis грамматически/семантически дефектны.** Это
   полностью объясняет AUROC≈0.497 (run 233, `mDeBERTa`) — модель не
   игнорировала сигнал, сигнала физически не было в самих вопросах.
2. **Направление `involves` было инвертировано.** §14.9 gloss: «атом
   вовлекает участника» — v1 писал «участник участвует в атоме»
   (обратно). v2: участник — грамматический субъект, атом — обстоятельство
   (`"{PERSON} участвует в описанном {ATOM_KIND}."`, как в примере
   владельца).
3. **Родовая ссылка на ATOM неоднозначна, если в кейсе больше одного
   атома того же kind** — найдено живым прогоном audit, не
   предполагалось заранее: `long_dense_window` имеет **7** атомов (не 6,
   как казалось по одним только gold-рёбрам) — `a7` (kind=event) не
   участвует ни в одном ребре, но делает родовую ссылку "описанное
   событие" неоднозначной даже для `a1`. Это и увело `long_dense_window`
   с 9 positive в v1 до **0** usable в v2.
4. **`located_at` не должен был применяться к CONCEPT-целям** — найдено
   тем же прогоном (первая версия verbalizer'а давала «Описанное понятие
   произошло в уролог.» — бессмысленно); исправлено, покрыто тестом
   `test_located_at_rejects_concept_targets_concepts_are_not_places`.
5. **`false_pair` v1 (30 примеров) строился на "нет в case.edges = ложно"
   — методологически недоказанное допущение.** В golden fixtures
   существует отдельный, специально для этого заведённый механизм —
   `ForbiddenEdge` (текст ЯВНО отрицает связь) — и он есть только у
   ОДНОГО кейса (`provocative_no_relation_invention`, пара
   Кузнецов Игорь/Волкова Елена). Только эти 2 примера (оба направления)
   методологически надёжны.
6. **wrong_type v1 (37 примеров) — 0 надёжных в v2.** Циклический сдвиг
   по реестру почти всегда попадал на комбинацию (relation_type,
   source_kind, target_kind), для которой в принципе нет естественной
   verbalization (`has_role`/`part_of` к ATOM никогда не регистрировались)
   — то есть v1 фактически не проверял «модель отвергает неверный тип»,
   а проверял «модель отвергает грамматическую бессмыслицу», два разных
   теста. Единственный содержательно валидный кандидат
   (`decision_rationale`, reason_for→supports) — QUESTIONABLE: факт
   «тестирование не завершено» правдоподобно ОДНОВРЕМЕННО и причина, и
   подтверждение решения перенести срок — не взаимоисключающие
   прочтения для этой конкретной пары.
7. **`related_to` и `contradicts` зафиксированы как симметричные**
   (владелец: `related_to` явно; `contradicts` — логически, 0 инстансов
   в golden fixtures сегодня) — `reversed_direction` для них исключён из
   hard-negative генерации: переставленная пара тоже истинна.

## Рекомендация (не решение)

Мандат (шаг 6) явно предусматривает этот исход: "сначала расширить
benchmark новыми OWNER-REVIEWABLE fixtures, но не генерировать expected
gold тестируемой моделью". Это не решается здесь самостоятельно.
Наблюдение: 10 из 15 relation_type (`has_role`, `part_of`, `created_by`,
`owned_by`, `resulted_in`, `supports`, `contradicts`, `supersedes`,
`derived_from`, `refers_to`) не имеют НИ ОДНОГО примера в golden fixtures
вообще (не только в v2 — в v1 их тоже физически не было, кроме
`resulted_in`/`supports`, чьи единственные инстансы утонули в
ambiguous-referent кейсе) — расширение fixtures для честного покрытия
всех 15 типов реестра потребовало бы MATERIAL новых кейсов, не только
починки существующих.
