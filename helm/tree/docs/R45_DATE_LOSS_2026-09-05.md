## 2. Что показал замер (health, 77/90)

### 2.1. Точность × наличие даты

| `date_precision` | узлов | из них с `occurred_at_start` |
|---|---|---|
| `NULL` | **881** | 0 |
| `day` | 1 | 0 |
| `unknown` | **0** | — |

Чтение по коду, а не по ощущению:

- **`NULL` возможен только если модель не дала `occurred_at`.** `parse_occurred_at(value, None)` при пустом `value` возвращает `(None, None)`; при непустом — либо дату, либо `(None, 'unknown')`. Третьего исхода нет. Значит 881 узел = атомы, у которых поля даты **не было в выдаче модели** — это П1, измеренный, не оценённый.
- **Клетка `unknown` пуста.** Именно туда попадает П4 всегда, без исключений. Ноль строк — значит ни один атом с неразобранной строкой даты до записи не дошёл. П4 = 0 на этом корпусе. Это не противоречит поправке владельца: она про то, что *внутри* клетки П1 и П4 неразличимы; пустая клетка даёт ноль обоим.
- Один узел `day` при пустой дате: модель поставила точность, не дав значения. Единичный случай, не картина.

### 2.2. Отказы валидатора — верхняя граница П2+П3

| | окон | из них с отказами | отказов всего |
|---|---|---|---|
| health | 134 | **101** | **722** |
| по статусу | `processed` 118 → 722 отказа; `failed` 16 → 0 | | |

722 отказа на 118 обработанных окон — **около шести на окно**. При ~880 принятых узлах валидатор отбрасывает порядка **45 % выдачи** модели. Причины не сохраняются (`semantic_publish.py:374` пишет только число), поэтому:

- сколько из 722 — датные гейты П2/П3, **неизвестно**; граница слишком грубая, чтобы что-то утверждать;
- часть из 722 — не потеря атома вовсе: «точность вне реестра» пишется в `rejected`, атом остаётся (`semantic_extract.py:535`).

Формулировка по правилу владельца: **П2/П3 не исключены**. Ноль здесь не получен, поэтому сказать «не являются причиной» нельзя.

### 2.3. Потолок: даты есть в самих текстах?

Первый замер дал 386 кусков из 953 и **90 из 90 источников** с «абсолютной датой». Но блок 5 напечатал примеры: `3.7`, `8.4`, `5.7`, `0.5`, `5.4`. Это лабораторные значения, не даты — регекс `\d{1,2}[./]\d{1,2}` ловит десятичную дробь. **Потолок завышен, число 386 не принимается.** Скрипт ужесточён (год `19xx/20xx` словом, `ДД.ММ.ГГГГ` целиком, название месяца) — честное число даст повторный прогон после R8.

**Находка по гейту П3, а не по скрипту:** продакшн-регекс `_ABSOLUTE_DATE_RE` (`semantic_extract.py:319`) содержит тот же `\d{1,2}[./]\d{1,2}`. То есть гейт «дата подтверждена абсолютной датой в цитате» принимает «глюкоза 5.4» за подтверждение. В медицинском корпусе это делает гейт почти всегда проходимым — он **слабее, чем задумано**, и с датами в узлах это не связано (их всё равно нет), но при появлении дат станет дырой: цитата с лабораторным значением «подтвердит» любую дату. Записано как долг, не правится в этом документе.

### 2.4. Источники: даты в тексте против дат в графе

Десять источников с наибольшим числом «датных» кусков (по завышенному регексу): 3–24 куска с датой на источник, 2–83 узла из источника — и **0 узлов с датой у каждого**. Имена файлов сами несут даты (`…(10.10.23 20_31).pdf`), в графе они не появляются.

## 3. Что из этого следует — и что не следует

**Следует.** Основная измеренная причина пустой временной оси — **П1: модель не пишет `occurred_at`**, хотя промпт просит (`semantic_extract.py:268`, 347). Это проблема извлечения, а не гейтов, и не парсера дат. Ослабление гейтов R4.5 **ничего не даст**: они не то, что режет даты в записанных узлах.

**Не следует.** Что гейты П2/П3 невиновны. 722 отказа — слишком много, чтобы отмахнуться; среди них могут быть атомы с датой, которые погибли целиком. Сколько — из БД не узнать.

**Единственный способ дойти до конца** — тот, что назвал владелец: минимальный диагностический повтор извлечения на выборке источников с двумя счётчиками до `parse_occurred_at()` (`no_date_from_model`, `date_parse_failed`) и с сохранением *причин* отказов, а не их числа. Это и разложит 722, и подтвердит П1 второй раз. Стоимость — локальная модель на 5–8 источниках, порядка 15–25 минут сервера; постоянное состояние не трогается, если повтор идёт в отдельную ревизию без переключения текущей.
