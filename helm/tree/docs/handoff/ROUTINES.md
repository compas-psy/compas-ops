# ROUTINES — регулярные фоновые задачи на сервере HELM

Systemd-юниты на VPS (`WORKPLAN.md`, "все пять юнитов заранее
проверены `systemctl`"). Это про HELM-инфраструктуру конкретно — не
путать с ночным циклом/бордом compas-ops (`charter/08_SCHEDULES.md`,
другой уровень — тот планирует работу АГЕНТОВ, эти — обслуживают сам
сервер).

**Оговорка по названию документа**: единственное другое место в
кодовой базе, где встречается слово «routines» — `ADR-101` упоминает
«P27 Autonomous routines» как будущую фазу (заметно дальше текущего
прогресса, ближе к Milestone D) без единой строчки реализации нигде в
репозитории. Не исключено, что §35 имел в виду именно ЭТУ будущую
фичу, а не нынешние systemd-юниты — в репозитории нет способа
различить эти два прочтения. Документ ниже описывает то, что реально
существует и работает сегодня; если окажется, что имелась в виду P27 —
переписать по факту появления той фичи, не раньше.

## Пять systemd-юнитов

| Юнит | Тип | Расписание | Что делает |
|---|---|---|---|
| `helm-guardian.service` + `.timer` | oneshot + timer | каждые 5 минут | Проверка диска/RAM/сервисов, алерт владельцу напрямую в Telegram при устойчивом превышении порога (ADR-011) |
| `helm-backup.timer` | timer | ежедневно, 03:30 MSK | Запускает `backup.sh` (§25/§26.1) |
| `sing-box@openrouter-proxy.service` | service | постоянно | Туннель в Финляндию для обхода блокировки OpenRouter по IP/датацентру (только для трафика `litellm`, см. `MODEL_ROUTING.md`) |

(Список из пяти в `WORKPLAN.md` называет их проверенными все разом при
живом деплое — двух остальных юнитов конкретные имена в найденных
документах не зафиксированы; если потребуется полный список — `sudo
systemctl list-timers` и `systemctl list-units '*helm*' '*sing-box*'`
на самом сервере.)

## Часовой пояс — Europe/Moscow (ADR-101)

Системный TZ сервера — `Europe/Moscow`, не `Europe/Helsinki` из спеки
по умолчанию (ADR-101, прямое распоряжение учредителя): owner-facing
время должно совпадать с реальным часовым поясом владельца. Время
морнинг-брифов/дайджестов HELM (D4: 07:30/09:00/18:00, §4.1) остаётся
тем же по часам, но теперь считается по московскому времени (разница
час от хельсинкского). Все последующие фазы (P4 Hermes cron и далее)
обязаны читать TZ из системной настройки сервера, не хардкодить
`Europe/Helsinki` заново.

## Что не бэкапится/не тикает автоматически

`restore_test.sh` — НЕ по расписанию, запускается вручную через
`deploy.yml action=restore-test` (см. `OPERATIONS.md`) — периодичность
не автоматизирована, это открытый пробел (проверять минимум после
каждой миграции схемы/изменения бэкап-скрипта).
