# PANEL — обзор веб-пульта

Устройство и решения — ADR-015 (статика+Caddy+Control Plane backend) и
ADR-016 (Telegram Login + WebAuthn/passkey). Этот документ — обзор для
того, кто впервые открывает `panel/` и должен быстро понять, что где.

## Что это

React + TypeScript + Vite фронтенд (`panel/`), собирается в статику
(`npm run build` → `dist/`), в проде node-процесса нет — Caddy отдаёт
файлы напрямую. Бэкенд — тот же Control Plane FastAPI (`api/panel.py`),
не отдельный сервис.

## Как собрать и проверить локально

```bash
cd panel
npm install
npm run build                      # tsc + vite → dist/
node tests/brief-compliance.mjs    # 27 проверок запретов дизайн-брифа
node tests/screenshot.mjs          # визуальная приёмка, 3 вьюпорта
```

## Источники дизайна и их старшинство (§10.5.1)

```
HELM v3.3 security/architecture
  > HELM_PANEL_DESIGN_BRIEF.md      поведение и содержание
    > HELM Panel.dc.html            визуальная композиция
      > _ds/*                       референс палитры
```

Все три — в `design-source/`, SHA256 сверены и записаны в
`design-source/SOURCE_HASHES.txt`. Известное расхождение с `_ds`:
bundled-палитра — продуктовая палитра СИМПАС (лес/золото/крем, только
светлая тема); бриф требует нейтральную шкалу + один accent + тёмную/
светлую по системной настройке. По §10.5.1 бриф старше — реализация
следует брифу, из `_ds` взят только accent-цвет.

## Как запреты брифа держатся в коде, не только на ревью

| Запрет | Чем удерживается |
|---|---|
| проценты без абсолюта | `MetricRow` требует `value: string`, автопроверка ловит форму `` `${x}%` `` |
| панель не зовёт модель | `panel.py` не импортирует модельный/сетевой клиент — тест по AST (ADR-020) |
| нет круговых индикаторов, карточек в карточках | таких примитивов нет в кодовой базе |
| step-up на каждую запись | `api.decide()` требует `stepUpId` в сигнатуре |
| нет mock-данных в бандле | заглушка только в `tests/`, перехват на уровне сети |
| анимации 150-200ms | автопроверка длительностей |

## Основные поверхности API (`api/panel.py`)

- **Approvals** — список/детали ожидающих RED-действий, включая
  `ActionTrust` (только чтение, ADR-010) и `NEVER_GRADUATE`-статус.
- **Knowledge** — `GET /api/panel/v1/knowledge` (память+источники,
  только чтение), `GET /knowledge/sources` (поиск), `POST /knowledge/
  sources/{id}/download` (оригинал, passkey-гейт, §14.15). Никакого
  мутирующего lifecycle для памяти/документов (ADR-023) — только
  account-level (suspend/reactivate/квота/удаление пользователя/экспорт
  архива, P8.6.7).
- **Сервер** — плоская таблица ресурсов (диск/RAM/inodes/Docker-disk),
  тот же принцип порогов, что у Guardian (ADR-011), не отдельная
  система метрик.
- **Auth** — `auth.py`, три потока: Telegram Login Widget → enrollment/
  passkey-логин → passkey step-up (ADR-016).

## Известные пробелы поверхности (не пропуски — не входили в объём)

- Мутирующее управление знаниями (забыть/вернуть/удалить/исправить)
  через Panel — нет, только через бота (ADR-023).
- UI для skill promotion — только макет в `design-source/*.dc.html`,
  в реальном роутере нет ни строки (ADR-008).
- Управление сессиями/устройствами (отозвать конкретный passkey из UI,
  не через `panel-passkey-recover.py`) — не реализовано.

## Recovery доступа

Если владелец теряет ВСЕ passkey — не через Panel UI, а
`scripts/panel-passkey-recover.py` на самом сервере (root). Подробности
— `PANEL_AUTH_RECOVERY.md`.
