# KNOWLEDGE_ADMIN — инженерный обзор administration-слоя

Это ИНЖЕНЕРНЫЙ документ (устройство кода). Пользовательская сторона
(что сказать боту) — `docs/KNOWLEDGE_ADMIN.md` в корне `docs/`, другой
файл, другая аудитория — не путать имена. Полный разбор архитектурного
решения — `ADR-023-knowledge-lifecycle-panel-bot.md`.

## Модуль

`helm_core/knowledge/admin.py` (§14.16). Ноль платного AI: разбор
команды — регулярные выражения, поиск цели — PostgreSQL full-text
search, решение о совпадении — сравнение чисел.

## Команды и их обработка

| Фраза | Действие над `KnowledgeMemory` | Обратимо |
|---|---|---|
| `Забудь <что>` / `Не используй <что>` | `status = DISABLED` | Да |
| `Верни в память <что>` / `Восстанови <что>` | `status = ACTIVE` | Да |
| `Удали навсегда <что>` | Физическое удаление строки + зеркала | **Нет** |
| `Исправь <что>: <новый текст>` (или `на` вместо `:`) | Текст записи заменяется, id остаётся тот же | Да, повторной правкой |

## Разрешение цели — общий алгоритм для всех команд

Тот же поиск, что отвечает на обычные вопросы (не отдельный индекс):

- **одно совпадение** — действуем, показываем текст затронутой записи
  (человек видит, что именно изменилось);
- **несколько совпадений** — перечисляем, просим уточнить;
- **ноль совпадений** — так и отвечаем.

Уточняющего диалога с сохранением состояния между сообщениями НЕТ —
человек просто повторяет команду точнее. Обоснование: половина команд
необратима (`Удали навсегда`), переспросить безопаснее, чем угадать по
неполному совпадению.

## Область действия — где это подключено

Одна и та же реализация обслуживает владельца (Telegram/MAX) и
KNOWLEDGE_USER (Dedicated Knowledge Bot) — единственная разница:
каждый видит и меняет только свои строки (RLS, ADR-030), не разный код.

## Что этот слой НЕ делает (см. ADR-023 для полного разбора)

- Не трогает `KnowledgeSource` (документы) — только `KnowledgeMemory`
  (Micro-Memory). Команды над документами («Переразбери», «Перенеси
  в…», «Обнови граф») из той же §14.16 не реализованы вовсе.
- Никакого мутирующего пути через Panel — `api/panel.py` даёт только
  чтение памяти/источников.

## Если потребуется расширить на документы

Поиск источника по имени уже есть (`documents.py`) — не хватает самих
команд-глаголов и решения, что именно означает «Переразбери»
(повторный проход `parse_file()` на уже сохранённом `raw_path`?) и
«Обнови граф» (зависит от Graphify, который сам ещё не начат, `E13 =
INSUFFICIENT_REAL_CORPUS`) — оба требуют отдельного проектирования, не
копирования паттерна с `KnowledgeMemory`.
