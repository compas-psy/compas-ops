# MCP — не реализовано, честно зафиксировано

**Статус: не начато.** Единственный след в кодовой базе —
`helm/tree/README.md`: MCP перечислен вместе с MAX как часть Milestone
P7, в разделе «Чего здесь нет и почему» — «не собрано офлайн то, что
требует живого сервера или отсутствующих секретов... MAX и MCP (P7)».

Больше НИ ОДНОГО упоминания MCP как HELM-фичи нигде в репозитории — ни
в `WORKPLAN.md`, ни в `V3.8-DELTA.md`, ни в коде `helm_core/`. (Панель
`design-source/HELM_PANEL_DESIGN_BRIEF.md` упоминает «каждый MCP» как
пункт будущего списка интеграций в UI мониторинга сервисов — тоже
только предположение о будущем состоянии, не реализация. Остальные
находки со словом «MCP» в репозитории — это `panel/node_modules/
playwright*`, инструментальная зависимость самого Playwright, не имеет
отношения к продукту HELM.)

## Что это, по всей видимости

Model Context Protocol — интеграция, дающая Hermes/chief-агенту
доступ к внешним MCP-серверам (аналогично тому, как Claude Code сам
использует MCP). Ни архитектура, ни список конкретных MCP-серверов, ни
способ их авторизации/секретов не определены нигде в этом репозитории
— поле для будущего проектирования, не сокращённая версия уже принятого
решения.

## Почему не написан ADR/дизайн-документ вместо этой заглушки

Решение отсутствует полностью, не только не задокументировано —
писать ADR или подробный дизайн было не из чего (тот же честный случай,
что ADR-002/ADR-007, см. `docs/adr/README.md`). Этот файл существует
только чтобы закрыть требование §35 списком документов явным
«не начато», а не молчанием — молчание в списке передачи выглядело бы
как забытый пункт, а не как сознательно неначатая работа.
