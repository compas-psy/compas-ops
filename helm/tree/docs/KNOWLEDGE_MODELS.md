# HELM Knowledge — Model choices (ТЗ §14.7, §14.9, §14.12)

**Ни одна модель здесь ещё не выбрана.** Это не пропуск — спека прямым
текстом запрещает хардкодить выбор до бенчмарка на живом сервере
(«P8.5 benchmark выбирает модель ... не hardcode»), а бенчмарк требует
реального 12GB VPS и живых пакетов — не делается офлайн. Документ
фиксирует кандидатов и методологию отбора, чтобы решение принималось по
факту, а не задним числом обосновывало то, что уже установили.

## Embeddings (dense retrieval, §14.9)

Ничего не установлено, `knowledge_chunks.embedding`-колонка не
существует (pgvector extension не создан — фиксированная размерность
вектора при создании колонки зависит от выбора модели: 1024 у BGE-M3
против 768 у e5-base; добавление колонки — отдельная миграция после
решения, не раньше).

Кандидаты из спеки:

| Модель | Роль | Размерность |
|---|---|---|
| `BAAI/bge-m3` | preferred quality candidate | 1024 |
| `intfloat/multilingual-e5-base` | fallback/lighter candidate | 768 |

Критерии отбора (§14.9, все обязательны — не только качество):

- Russian retrieval quality
- RAM
- CPU latency
- indexing speed

Отдельно после выбора модели — решение по embedding worker: постоянный
лёгкий процесс (если измеренный запас RAM позволяет) или on-demand с
выгрузкой после простоя. Спека прямо предупреждает: не держать BGE-M3
резидентно только потому, что он выиграл по качеству, если это создаёт
memory pressure — используется лучшая модель, прошедшая ОБА гейта
(качество И ресурсы), не только качество.

## Audio ASR — GigaAM (§14.7)

Версия не выбрана, пакет не установлен. Спека: «актуальная stable
GigaAM v3/e2e line на дату установки»; для русского — e2e вариант с
punctuation/text normalization, если бенчмарк подтверждает качество;
word timestamps — если доступны в выбранной версии.

Контракт по ресурсам (не зависит от выбора конкретной версии):
`concurrency=1`, on-demand запуск, выгрузка из RAM после использования,
не резидентна на 12GB VPS. Guardian не запускает ASR при CRITICAL
memory pressure.

## Z2 — опциональный локальный генератор (§14.12)

Не установлен, не выбран. Спека делает его явно необязательным: «Z2 is
not allowed to delay B.5 completion» — если ни одна квантованная
multilingual instruction-модель под `llama.cpp`-совместимый runtime не
проходит golden-benchmark против cloud baseline на измеренном железе,
Z2 остаётся выключенным навсегда для этого класса вопросов, и это
корректное, ожидаемое спекой состояние, а не недоделка. Z0/Z1
(реализованы, `docs/KNOWLEDGE_RETRIEVAL.md`) уже дают бесплатные
ответы без Z2.

Если/когда бенчмарк будет запущен: one-shot runtime (не постоянный
Ollama daemon), concurrency=1, cgroup-лимиты, приоритет CPU ниже
Control Plane/Hermes messaging, модель видит только evidence pack, не
весь vault.

### Design note — "human-alike" ответ (запрос владельца 29.08.2026)

По итогам первого живого использования P8.5.7 владелец отметил: сегодня
`_compose_answer()` (`probe.py`) для Z0/Z1 отдаёт СЫРУЮ цитату из
документа + имя файла-источника — технически корректно (§14.12: «no
paraphrase risk» ровно потому, что это дословная цитата), но читается
не как ответ живого собеседника. Запрошено: пропускать этот же
extractive-результат через бесплатную локальную модель (кандидат
владельца — Ollama), чтобы получить естественный, человечный тон, БЕЗ
похода к OpenRouter/платным моделям.

Это ровно то, что спека уже называет Z2 (§14.12) — не новый уровень,
уточнение требований к нему:

```text
Z0/Z1 (уже реализовано, детерминированно, без LLM)
  → находит evidence (chunk + citation), извлекает как есть
  → [НОВОЕ] Z2-рефраз, если бенчмарк прошёл:
      локальная модель ПЕРЕФРАЗИРУЕТ найденный evidence в
      естественный тон — НЕ ищет новых фактов, НЕ видит vault
      целиком, только то, что Z0/Z1 уже нашли и процитировали.
      Модель не прошла бенчмарк / не установлена → Z0/Z1-текст
      уходит владельцу как есть (текущее поведение, корректный
      деградированный путь, не ошибка).
  → LOCAL_ANSWER (paid_ai_used=False в обоих случаях — рефраз
    локальной моделью не платный вызов, метрика §14.14 не меняется)
```

Почему рефраз, а не свободная генерация: Z2 в этой роли получает на
вход ТОЛЬКО текст evidence + исходный вопрос владельца, явно не имеет
доступа ни к остальной базе знаний, ни к инструментам — по конструкции
не может «отвечать от себя» или добавлять факты, которых нет в
extractive-результате Z0/Z1. Это сильно снижает риск галлюцинации
относительно «свободного» Z2 (спекой описанного как альтернатива
эскалации на C1) — здесь роль модели чисто стилистическая, не
содержательная.

Кандидат рантайма — Ollama (предложение владельца), архитектурно
совместим с уже описанным контрактом ресурсов выше (one-shot,
concurrency=1, cgroup-лимиты). Выбор конкретной модели/квантования — тот
же принцип §14.9/§14.12, что и везде в этом документе: реальный
бенчмарк на живом VPS (latency рефраза + RAM + subjective quality на
русском), не выбор по репутации. Если ни одна модель не проходит гейт
по ресурсам — Z0/Z1 остаётся финальным бесплатным ответом, это
допустимый исход, не блокер.

**Статус: спроектировано, не реализовано.** Следующий конкретный шаг —
не сейчас (по прямой просьбе владельца, "это можно позже") — см.
`implementation-state/WORKPLAN.md`, раздел «HELM Knowledge (P8.5)».

## Graphify (§14.10) — challenger, не модель, но тот же принцип отбора

Не установлен. Разрешён только как derived/on-demand индекс — сравнение
`FTS + pgvector + relations` против того же + Graphify structural paths
на реальных multi-hop golden cases. Включается в hot path только если
измеримо улучшает эти конкретные случаи; решение фиксируется в
`ADR-015` (документ ещё не создан — создаётся вместе с самим
экспериментом, не раньше).

## Как обновлять этот документ

Каждое решение здесь — результат прогнанного на живом сервере
бенчмарка с конкретными числами (RAM, latency, retrieval quality на
реальном корпусе), а не выбор «на глаз» или по репутации модели.
Обновлять этот файл в том же коммите, где меняется код, использующий
выбранную модель — не раньше и не позже.
